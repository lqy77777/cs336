# §4.2 SGD 优化器与 `torch.optim.Optimizer` API 详解

> 对应 handout 第 29–31 页。本节是**唯一一个 handout 直接把完整实现给你看**的地方——因为它的目的不是让你写 SGD，而是让你搞懂 Optimizer 的 API 契约，为 §4.3 的 AdamW 打地基。所有数值实验都实际跑过。

---

## 一、SGD 的数学

从随机初始化的参数 $\theta_0$ 出发，每一步 $t = 0, \dots, T-1$：

$$\theta_{t+1} \leftarrow \theta_t - \alpha_t \nabla L(\theta_t; B_t) \tag{19}$$

三个要素：

| 符号 | 含义 | 性质 |
|---|---|---|
| $B_t$ | 从数据集 $D$ 中随机采样的一个 batch | 这就是 "Stochastic" 的来源 |
| $\alpha_t$ | 学习率，可随 $t$ 变化 | 超参数 |
| $\|B_t\|$ | batch size | 超参数 |

**为什么是 "Stochastic"**：真正的梯度应该是在整个数据集上算的 $\nabla L(\theta; D)$，但那太贵。用一个 batch 的梯度作为它的**无偏估计**——期望正确，但每一步都带噪声。这个噪声不全是坏事，它能帮助逃离尖锐的局部极小。

handout 的示例用了一个带衰减的变体，让步长随时间变小：

$$\theta_{t+1} = \theta_t - \frac{\alpha}{\sqrt{t+1}} \nabla L(\theta_t; B_t) \tag{20}$$

这个 $1/\sqrt{t+1}$ 纯粹是为了把「**每个参数需要携带自己的状态**」这件事演示出来——因为 $t$ 必须被记住。真正的 AdamW 需要记住的状态更多（一阶矩、二阶矩），机制完全一样。

## 二、`torch.optim.Optimizer` 的 API 契约

子类必须实现两个方法。

### 2.1 `__init__(self, params, ...)`

职责是**把参数和默认超参数交给基类**：

```python
def __init__(self, params, lr=1e-3):
    if lr < 0:
        raise ValueError(f"Invalid learning rate: {lr}")
    defaults = {"lr": lr}
    super().__init__(params, defaults)
```

三个要点：

1. **`params` 可以是两种东西**：一个 `Parameter` 的可迭代对象（如 `model.parameters()`），**或者**一个「参数组」列表——后者允许模型不同部分用不同超参数（比如 embedding 层用更小的学习率，或者只对权重做 weight decay 而不对 bias 做）。
2. **超参数以 dict 形式传给基类**，key 的名字由你自己定。基类会把它们存进每个参数组里，`step` 时通过 `group["lr"]` 取出来。
3. **参数校验放在 `__init__`**。这是好习惯：非法的学习率应该在构造时就炸，而不是训练 3 小时后炸。

> 如果传进来的只是一个普通的 Parameter 集合，基类会自动创建**单个组**并把 defaults 赋给它。所以 `self.param_groups` 永远是个列表，哪怕只有一个元素。

### 2.2 `step(self)`

在训练循环里，它会在**反向传播之后**被调用，所以此时每个参数的 `.grad` 都已经算好了。职责是**逐个参数、原地修改**。

### 2.3 两个关键数据结构

| 结构 | 类型 | 存什么 | 谁维护 |
|---|---|---|---|
| `self.param_groups` | `list[dict]` | 每组的 `"params"` 列表 + 该组的超参数 | 基类 |
| `self.state` | `dict[Parameter, dict]` | **每个参数各自的**优化器状态 | 你自己 |

`self.state` 是理解优化器的核心。它以**参数张量本身**为 key（利用了 Tensor 的默认 hash），值是一个任你填的字典。SGD 只需要存一个步数 `t`；AdamW 会在这里存两个和参数同形状的矩估计张量——这就是为什么 **AdamW 的显存开销是参数量的 2 倍**（§4.3 的 `adamw_accounting` 会让你算这笔账）。

### 2.4 `closure` 参数

```python
def step(self, closure: Optional[Callable] = None):
    loss = None if closure is None else closure()
```

API 允许调用方传一个 callable，让优化器在更新前**重新计算一次 loss**。像 L-BFGS 这类需要在一步内多次评估目标函数的优化器才用得上。我们用不到，但为了**符合 API 契约**还是要接受并转发它——这样你的优化器才能被任何按标准写法调用它的代码正确使用。

## 三、逐行解读 handout 的示例

```python
def step(self, closure=None):
    loss = None if closure is None else closure()
    for group in self.param_groups:          # ① 遍历参数组
        lr = group["lr"]                     # ② 取出这一组的超参数
        for p in group["params"]:            # ③ 遍历组内每个参数张量
            if p.grad is None:               # ④ 没有梯度就跳过
                continue
            state = self.state[p]            # ⑤ 取出这个参数的状态字典
            t = state.get("t", 0)            # ⑥ 懒初始化：第一次取不到就用 0
            grad = p.grad.data               # ⑦ 拿到梯度张量
            p.data -= lr / math.sqrt(t + 1) * grad   # ⑧ 原地更新
            state["t"] = t + 1               # ⑨ 写回状态
    return loss
```

**这个「双层循环 + 状态读改写」的骨架，就是所有 PyTorch 优化器的通用模板。** AdamW 与它的差别只在第 ⑧ 步的更新公式和第 ⑤–⑨ 步维护的状态内容。

## 四、四个必须理解的细节

### 4.1 为什么是 `p.data -=` 而不是 `p = p - ...`

这是新手最容易踩的坑，而且**不报错**。

```python
p = p - lr * grad        # ❌ 只是让局部变量 p 指向一个新张量，模型参数纹丝不动
p.data -= lr * grad      # ✅ 原地修改参数张量持有的那块内存
```

第一种写法里，`p` 是 for 循环的局部变量。重新绑定它，只是改变了这个名字指向谁，**模型里那个 `Parameter` 对象根本不知道发生了什么**。症状是：训练跑得好好的，loss 一动不动。

用 `.data`（或 `torch.no_grad()` 上下文）的第二个原因是**绕过 autograd**。参数是 `requires_grad=True` 的叶子节点，直接对它做原地运算会被 autograd 拦截报错；`.data` 拿到的是脱离计算图的同一块内存的视图。

> 回忆 [gather与高级索引详解.md](gather与高级索引详解.md) §2.6：高级索引返回**拷贝**，但作为赋值左值时是**原地写入**。这里是同一个「原地 vs 拷贝」的主题在优化器上的体现——写错了同样是静默失败。

### 4.2 `p.grad is None` 的三种成因

跳过这个检查会直接 `AttributeError`。梯度为 `None` 的常见原因：

- 这个参数**没有参与本次前向计算**（比如模型里有条分支这一步没走到）
- 参数被 `requires_grad_(False)` 冻结了
- **还没跑过 `backward()`**——比如你不小心在第一次 backward 之前就调了 `step()`

注意 `None` 和「全零梯度」是不同的：前者表示「这个参数这一步不该被更新」，后者表示「该更新，但梯度恰好是 0」。所以正确的做法是 `continue` 跳过，而不是当成零处理。

### 4.3 `zero_grad()` 为什么必须显式调用

PyTorch 的梯度是**累加**的：`backward()` 做的是 `p.grad += 新梯度`，而不是 `p.grad = 新梯度`。不清零的话，第 $t$ 步用的就是前 $t$ 步梯度的总和，学习率相当于被放大了 $t$ 倍——训练会以一种很难 debug 的方式崩掉。

**为什么 PyTorch 要这么设计？** 因为累加语义让「梯度累积」这个技巧天然可行：显存装不下大 batch 时，可以跑 4 个小 batch、连续 backward 4 次、再 step 一次，效果等价于一个 4 倍大的 batch。

> 这和 [gather与高级索引详解.md](gather与高级索引详解.md) §2.7 讲的 `scatter_add` 是同一套哲学：**梯度默认累加**。同一个 token 在序列里出现多次时 embedding 梯度能正确相加，靠的正是这个语义。

### 4.4 `state.get("t", 0)` 的懒初始化

`self.state` 是个 `defaultdict`，第一次访问 `self.state[p]` 会得到空字典。所以不需要在 `__init__` 里预先为每个参数建状态——**第一次 `step` 时用 `.get(key, 默认值)` 惰性创建即可**。这个模式在 AdamW 里会原样复用（第一次访问时把矩估计初始化为零张量）。

## 五、训练循环的标准结构

```python
for t in range(100):
    opt.zero_grad()      # ① 清空上一步的梯度
    loss = ...           # ② 前向：算出标量 loss
    loss.backward()      # ③ 反向：填充所有 p.grad
    opt.step()           # ④ 更新：按 p.grad 修改 p
```

**这四步的顺序不能乱**，每一步都依赖前一步的产物：

- ① 必须在 ③ 之前（否则梯度累加）
- ③ 必须在 ② 之后（没有计算图就没法反传）
- ④ 必须在 ③ 之后（`step` 读的是 `p.grad`）

另外注意 ② 里 **loss 必须是标量**——这正是我们讨论 `cross_entropy` 返回值时的那个结论。非标量调 `backward()` 会报 `grad can be implicitly created only for scalar outputs`。

训练语言模型时，这个骨架**一个字都不用变**：参数来自 `model.parameters()`，loss 换成在采样 batch 上算的 cross-entropy。§5 的 `training_together` 就是把这个循环填充完整。

## 六、Problem (learning_rate_tuning)：理论与实测

handout 让你在玩具例子上用 `lr = 1e1, 1e2, 1e3` 各跑 10 步，观察 loss 行为。这个例子可以**完全解析地**算出来，非常值得推一遍。

### 6.1 推导

玩具 loss 是 $L = \frac{1}{100}\sum_{i} w_i^2$（$10\times10$ 共 100 个元素），于是

$$\frac{\partial L}{\partial w_i} = \frac{2 w_i}{100} = 0.02\, w_i$$

代入式 (20) 的更新规则：

$$w_i \leftarrow w_i - \frac{\alpha}{\sqrt{t+1}} \cdot 0.02\, w_i = w_i \underbrace{\left(1 - \frac{0.02\,\alpha}{\sqrt{t+1}}\right)}_{\text{收缩因子 } c_t}$$

**每一步 loss 会乘以 $c_t^2$。** 收敛条件就是

$$|c_t| < 1 \quad\Longleftrightarrow\quad 0 < \frac{0.02\,\alpha}{\sqrt{t+1}} < 2 \quad\Longleftrightarrow\quad \boxed{\alpha < 100\sqrt{t+1}}$$

第一步（$t=0$）的临界学习率恰好是 **100**。

### 6.2 实测（seed=0，初始 loss ≈ 26.27）

| lr | $c_0$ | 10 步后的 loss | 行为 |
|---|---|---|---|
| `1` | $0.98$ | 21.74 | 收敛，但**极慢**（每步只缩 4%） |
| `1e1` | $0.8$ | 3.53 | 收敛，明显更快 |
| `1e2` | $-1.0$ | $2.4\times10^{-23}$ | **先原地不动，然后迅速塌缩** |
| `1e3` | $-19$ | $2.4\times10^{18}$ | **发散** |

### 6.3 三个值得琢磨的现象

**(a) `lr=1e2` 的头两步 loss 一模一样（26.3 → 26.3）**

因为 $c_0 = 1 - 2 = -1$：参数**整体翻了个符号但绝对值不变**，loss 完全不变。这是收敛与发散的**临界点**。从 $t=1$ 开始 $\sqrt{t+1}$ 让步长变小，$|c_t|$ 迅速掉到 1 以下，于是塌缩得飞快。

**(b) `lr=1e3` 为什么救不回来**

按收敛条件，要等到 $\alpha < 100\sqrt{t+1}$，即 $t \ge 100$ 才开始收缩。可是前 100 步里参数每步都在放大（$|c_0| = 19$），10 步后 loss 已经是 $10^{18}$——真实训练中这时早就 `inf` / `nan` 了。**衰减的学习率救不了一个一开始就爆炸的训练。**

**(c) 最快的不是最小的**

`lr=1` 十步后 loss 才降到 21.7，而 `lr=1e2` 降到了 $10^{-23}$。**学习率太小和太大同样是问题**——前者是「训练不动」，后者是「训练炸掉」，中间那个甜点区往往只有一两个数量级宽。这就是为什么 §6 的 `learning_rate` 实验值得花 2 个 B200 小时去扫。

> **交付物提示**：handout 只要 1–2 句话描述观察到的行为。但强烈建议你自己把这个脚本跑一遍并把每步 loss 打出来——上面 (a) 那个「前两步纹丝不动」的现象，不亲眼看到是很难相信的。

### 6.4 推广到真实训练

这个玩具例子的 loss 是完美的二次函数，所以能解析求解。真实网络当然不是，但**结论的形状是一样的**：

- 存在一个临界学习率，超过它训练发散
- 这个临界值由 loss 曲面的**曲率**决定（二次情形下就是 Hessian 的最大特征值 $\lambda_{\max}$，收敛条件是 $\alpha < 2/\lambda_{\max}$）
- 真实网络的曲率在训练过程中会变化，所以才需要 **warmup**（一开始曲率大，先用小学习率）和**衰减**（后期精调）——这正是 §4.4 学习率调度要解决的问题

## 七、易错点清单

1. **`p = p - lr*grad`** 只重绑局部变量，参数不变。必须 `p.data -= ...` 或在 `torch.no_grad()` 里改。**静默失败，无报错。**
2. **忘记 `if p.grad is None: continue`** → `AttributeError: 'NoneType' object has no attribute 'data'`。
3. **忘记 `opt.zero_grad()`** → 梯度累加，等效学习率随步数线性增长。
4. **`zero_grad()` 放在 `backward()` 之后** → 把刚算出来的梯度清掉了，参数永远不更新。
5. **超参数硬编码在 `step` 里**而不是从 `group[...]` 读 → 参数分组功能失效。
6. **在 `__init__` 里为每个参数预建 state** → 不必要；用 `state.get(key, default)` 惰性初始化。
7. **loss 不是标量**就调 `backward()` → `RuntimeError`。
8. **不接受 `closure` 参数** → 违反 API 契约，某些调用方式下会报 `TypeError`。

## 八、通向 AdamW 的路

§4.3 要实现的 AdamW，和这里的 SGD **骨架完全相同**，差别只有两处：

| | SGD (示例) | AdamW |
|---|---|---|
| `self.state[p]` 存什么 | 一个整数 `t` | `t` + 两个**与参数同形状**的张量（一阶矩、二阶矩） |
| 更新公式 | $\theta \mathrel{-}= \frac{\alpha}{\sqrt{t+1}} g$ | 矩估计 + 偏差校正 + 解耦的权重衰减 |

所以本节真正要带走的东西是**那个双层循环模板**和**「状态挂在参数上」的心智模型**，而不是 SGD 本身。写 AdamW 时，如果你发现自己在纠结「这个变量该存哪」，答案几乎总是 `self.state[p]`。
